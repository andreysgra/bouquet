# Техническое задание к проекту «Цветочный магазин»

## О проекте

«Цветочный магазин» — сайт магазина букетов. Пользователь может просматривать все доступные букеты или отфильтрованные по заданным параметрам. Понравившиеся букеты пользователь может добавить в отложенное.

## 1. Описание функциональности
1. Проект состоит из трёх экранов:

2. Главная страница с каталогом

3. Экран отложенных товаров

Модальное окно карточки товара (открывается поверх страницы с каталогом)

### 1.1 Общий контейнер

1.1.1 В хэдере находится информация о количестве отложенных букетов и информация об итоговой стоимости этих отложенных букетов.

1.1.2 При клике на кнопку-иконку `отложить` в карточке товара каталога или при клике на кнопку `отложить` в попапе количество букетов увеличивается, сумма увеличивается на стоимость этого букета. При повторном клике на кнопку-иконку на карточке или при клике на кнопку `отложено` в попапе, в хэдере количество букетов уменьшается и уменьшается сумма на стоимость этого букета.

1.1.3 При клике на иконку отложенных букетов в хэдере — открывается список всех отложенных букетов.

### 1.2 Букеты

1.2.1 После загрузки приложения в списке отображается не более `6` карточек букетов.

1.2.2 Показ оставшихся букетов выполняется кликом на кнопку `показать ещё`. При нажатии показываются очередные `6` букетов или оставшиеся букеты, если их количество меньше `6`.

1.2.3 После показа всех карточек с букетами, кнопка `показать ещё` скрывается.

1.2.4 Любое изменение фильтра или сортировки сбрасывает счётчик показанных букетов, и отсчёт начинается заново.

1.2.5 В случае отсутствия букетов вместо списка отображается текст: «К сожалению, таких букетов у нас пока нет».

### 1.3 Сортировка

1.3.1 Для пользователя доступна сортировка по цене продукта.

1.3.2 Сортировка активируется при клике на указатели сортировки от большего к меньшему (по убыванию) или от меньшего к большему (по возрастанию).

1.3.3 По умолчанию карточки букетов расположены рандомно относительно цены продукта.

1.3.4 После получения списка букетов необходимо сразу произвести их сортировку.

### 1.4 Карточки букетов

Карточки букетов представлены в двух вариантах: стандартный (в списке букетов) и расширенный (отдельный попап с дополнительными фотографиями букетов).

**1.4.1 Стандартный вариант карточки букетов**

В стандартном варианте карточка с букетом содержит следующую информацию:

— Превью букета;

— Именование букета;

— Краткое описание (не более 140 символов). Если описание букета больше 140 символов, то в карточке отображается 139 символов описания и знак многоточие (…).

— Цена букета;

— В карточке букета отображается кнопка-иконка управления, состояние иконки для каждого действия отрисовано в ui-kit макета проекта:

«Отложить» — добавляет букет в список отложенных товаров, после совершения действия меняется на кнопку «Отложено»;

«Отложено» — помечает букет как отложенный. Повторное нажатие удаляет букет из списка, кнопка возвращается к состоянию «Отложить»;

**1.4.2 Расширенный вариант карточки букетов**

Клик по карточке букета (за исключением кликов по кнопкам управления) открывает попап с подробной информацией о букете;

Попап содержит:

— Галерею фотографий выбранного букета;

— Автора фотографии;

— Именование букета;

— Краткое описание;

— Цену букета;

— В попапе отображаются кнопки управления:

`Отложить` — добавляет букет в список отложенных товаров, после совершения действия меняется на кнопку `Отложено`;

`Отложено` — помечает букет как отложенный. Повторное нажатие удаляет букет из списка, кнопка возвращается к состоянию `Отложить`;

— Попап можно закрыть нажатием на кнопку `закрытия` в правом верхнем углу (крестик) или с помощью кнопки `Esc` на клавиатуре. При закрытии попап удаляется из DOM.

— Одновременно может быть открыт только один попап. При открытии нового попапа прежний закрывается, например, при клике на другую карточку при открытом попапе.

### 1.5 Фильтры

1.5.1 В приложении предусмотрено два фильтра:

«Выберите событие» — выбираем повод для заказа букета (варианты — `для всех`, `имениннику`, `любимой`, `маме`, `коллеге`, `невесте`). Может быть выбрано только одно значение.

«Выберите цвет букета» — выбираем цвет для основы букета (варианты — `жёлтый`, `красный`, `белый`, `розовый`, `сиреневый`, `все цвета`). Может быть выбрано несколько значений.

1.5.2 Фильтр должен переключаться при клике на надпись.

— Если фильтру соответствует больше `6` букетов, то в списке букетов по этому фильтру отображаются первые 6 букетов, а остальные показываются по нажатию на кнопку `показать ещё`, как и в списке букетов по умолчанию.

— Если в отфильтрованном списке отсутствуют подходящие карточки, вместо списка отображается соответствующий текст.

### 1.6 Попап отложенных товаров

1.6.1 Список представляет собой экран букетов со статусом «Отложено».

1.6.2 Попап доступен при клике на иконку отложенного товара в хэдере.

1.6.3 На экране отображаются кнопки управления:

`Очистить` — очищает весь список букетов в списке;

`В каталог` — возвращает на главную страницу каталога в первоначальном состоянии без активированных фильтров и сортировок;

Иконка закрытия попапа.

1.6.4 Карточка букета содержит:

Превью выбранного букета;

Именование букета;

Краткое описание;

Количество конкретного букета;

Цену букета;

Кнопку-иконку удаления конкретной карточки из списка;

1.6.5 Информация о количестве и общей стоимости товаров:

Количество букетов в списке отложенных;

Итоговая сумма за все букеты;

### 1.7 Взаимодействие с сервером

Сервер проекта доступен по [адресу](https://grading.objects.htmlacademy.pro/).

Спецификация по взаимодействию с сервером в формате [OpenAPI](https://grading.objects.htmlacademy.pro/spec/flowers-shop#auth) — это одновременно и инструкция по использованию, и песочница, где вы можете тестировать запросы к API. Для этого достаточно указать в песочнице в поле username строку авторизации `Basic ${случайная строка}`. Например, `Basic er883jdzbdw`.

### 1.8 Обратная связь интерфейса

— На время загрузки вместо букета нужно вывести информационное сообщение. Дизайн сообщения остаётся на усмотрение студента.

— При нажатии на кнопки «Очистить», «Удалить» формируется запрос к серверу на добавление, изменение или удаление данных. На время выполнения запроса текст заголовка кнопки изменяется:

  — «Очистить» -> «Очищаем...»

  — «Удалить» -> «Показывает иконку loader…»

— Заголовки кнопок возвращаются в исходный вид после завершения запроса.

— В момент отправки запроса на просмотр, добавление или отмену данных по букету форма и интерфейс блокируются от внесения изменений. Разблокировка интерфейса и формы происходит после завершения выполнения запроса, независимо от того, успешно он выполнен или нет.

— Обновление элементов в DOM происходит только после успешного выполнения запроса к серверу.
